# Directory listing assets

Files that other MCP / agent directories need from us but that do not belong in the app.
Each is copied out of the repo at submission time; the runbook is docs/08 → "Directory
listings". The manifests that stay at the repo root are `server.json` (official MCP Registry),
`glama.json` (Glama repo claim) and `.claude-plugin/marketplace.json` (Claude Code marketplace).

| Path                                     | Directory                                           | How it is used                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| :--------------------------------------- | :-------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `smithery/config-schema.json`            | Smithery (smithery.ai)                              | Passed as `--config-schema` to `smithery mcp publish`. Declares the one field the user fills in (their NextBlock MCP token). Smithery receives it on `x-nextblock-token` (`authorization` is reserved for Smithery's own OAuth) and forwards it upstream as a raw `Authorization` header; `parseBearerToken` in `libs/cortex` accepts a token with or without the `Bearer ` prefix, so this works unchanged.                                                                                                                                                        |
| `docker-mcp-registry/servers/nextblock/` | Docker MCP Catalog (github.com/docker/mcp-registry) | Copy the whole folder to `servers/nextblock/` in a fork of docker/mcp-registry and open a PR. `type: remote` with the vendor instance URL; `tools.json` is `[]` because remote servers use dynamic discovery; `dynamic.tools: true` keeps their validator from trying an unauthenticated `tools/list`. Do **not** add `source.project`: it turns on Docker's license check, whose blocklist rejects AGPL. The user's token is the Docker secret `nextblock.mcp_token`, injected as `NEXTBLOCK_MCP_TOKEN`. Keep LF line endings and no BOM (their CI runs Prettier). |
