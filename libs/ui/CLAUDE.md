# libs/ui — @nextblock-cms/ui

Client React primitives (Radix + cva + lucide), composite CMS controls (`ColorField`,
`SearchableSelect`, `ConfirmationDialog`), a legacy `tailwind.config.js` preset, and the global
stylesheets in `src/styles/` (`globals.css` is the one CSS entry the app imports).

Entry points: `@nextblock-cms/ui` (barrel `src/index.ts`; register every new component there);
`@nextblock-cms/ui/<component>` resolves to `src/lib/<name>` in the monorepo but to the barrel in
the published package; `@nextblock-cms/ui/styles/*`.

## Rules
- The build prepends `"use client"` to the bundle (most components also start with it);
  styling is `cn()` + cva variants over theme tokens (`hsl(var(--token))`); token values are
  bare HSL triplets, never hex.
- `tsconfig.lib.json` includes `../utils/src/**` with `references: []`; `libs/editor` includes
  `../ui/src/**` the same way, so a type error here also breaks the editor build.
- The published manifest is generated by `vite.config.mts` afterBuild; editing `package.json`
  exports changes nothing for consumers.

## Gotchas
- Tailwind v4 loads only the ROOT `tailwind.config.js` (via `@config` in `globals.css`); the same
  theme is duplicated in `libs/ui/tailwind.config.js` and the string in `apps/create-nextblock/bin`.
  Edit all three.
- `safelist` in any Tailwind JS config is dead under v4; dynamic classes must appear as literals.
- `src/styles/theme.css` is only a fallback; DB `site_themes` rows override it at runtime.

Commands: `npx nx build ui`, `npm run nx:lint:ui`, `npx nx typecheck ui`. No tests exist.
