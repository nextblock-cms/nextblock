# libs/editor — @nextblock-cms/editor

Client-only Tiptap v3 editor: `NotionEditor` (what the app mounts), the `editorExtensions` kit
(`src/lib/kit.ts`), HTML-preserving nodes (`DivNode`, `SpanNode`, `SvgNode`; kit-internal),
block widgets (`AlertWidget`, `CtaWidgetNode`), menus, `useEditorHistory`,
`LowContrastTextHint`. Stylesheets ship as `@nextblock-cms/editor/styles/*`.

`NotionEditor` props: `content` | `initialContent` (HTML or Tiptap JSON), `onChange(html)`,
`onUpdate(json)`, `onEditorReady`, `openImagePicker`, `extensions` (replaces the kit) vs
`dynamicExtensions` (appends). The app mounts it only via `next/dynamic` with `ssr: false`.

## Rules
- Depends on `@nextblock-cms/ui` and `@nextblock-cms/utils`; `tsconfig.lib.json` is the reference
  composite config (sibling sources in `include`, no `references` key).
- Prefer `@tiptap/pm/*` over `prosemirror-*` (two menus still import `prosemirror-state`).
- `LowContrastTextHint` must not touch the schema (its test fingerprints the kit schema).
- The dist manifest is generated by `vite.config.mts`; Tiptap deps are bundled.

## Gotchas
- `apps/nextblock/app/cms/blocks/editors/TextBlockEditor.tsx` hand-copies `NotionEditorProps`
  for `next/dynamic`; a new prop fails to type-check until added there.
- `window.__nextblockEditor` is last-mount-wins; use `onEditorReady` instead.
- The AI prompt bar hard-codes `fetch('/api/ai/generate-blocks')`; the lib depends on that route.

Commands: `npx nx build editor`, `npm run nx:lint:editor`, `npx vitest run libs/editor`.
